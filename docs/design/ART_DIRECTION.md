## 01. Design North Star（方向核心）

**一句話定位：** 這是一間「有主人溫度的小型住宿」——不是精品飯店，也不是 Airbnb 房源模板。

**網站第一感受應該像：**
- 翻閱一本拍得很好的旅行小誌
- 進入一間安靜、有人生活過的房子
- 有設計感，但不刻意炫耀設計

**優先順序：**
1. 空間與住宿照片（照片是主角）
2. 閱讀舒適度
3. 溫暖與真實感
4. 品牌辨識
5. 視覺技巧與動畫

**取捨規則（衝突時選哪個）：**
- 當「漂亮」和「好閱讀」衝突時 → 選好閱讀
- 當「高級」和「有人味」衝突時 → 選有人味
- 當「設計感」和「真實感」衝突時 → 選真實感

## 02. Visual Positioning（光譜定位）

```
家庭民宿 ←──────●────── 精品飯店
自然樸實 ←─────●─────── 奢華精緻
Editorial ←───●──────── SaaS / App
安靜 ←────●────────── 活潑
真實攝影 ←─●────────── 高度視覺特效
```

**我們不是：**
- 精品飯店官網（深色、奢華襯線、極致留白）
- 科技 SaaS Landing Page
- Airbnb 卡片式介面
- Instagram 網紅打卡頁
- 極簡建築事務所網站

## 03. Reference Board（參考）

### REF-01 — 現站 warm-v1（Benchmark）
- 借用：Hero 照片主導、米白背景與攝影的溫度、標題內文字級差、慢節奏
- 不要照搬：個別 section spacing 細節、現有按鈕樣式（可演化）

### REF-02 — 信紙式 Host Message 區塊
- 借用：手寫字（Klee One）、金線框、簽名、印章角落、邊線引導
- 不要照搬：過度裝飾化、每區都手寫

### REF-03（負面）— 深色實驗版（sen33-3-v2）
- 為何否決：偏離溫暖住宿感、視覺人格變化過大、更像精品飯店/設計網站、品牌一致性下降
- 教訓：**未來 redesign 預設以 warm benchmark 演化，不重新發明視覺世界**

## 04. Visual Grammar（視覺語法——方向，不是數值）

- **Typography：** 三層系統——襯線標題（Noto Serif TC）有編輯感但不張揚；手寫區（Klee One）給人味與簽名；正文樸素系統字。字距普遍拉大（tracking 0.08-0.2em）是慢節奏來源。不用大量 uppercase、不靠超巨大字體製造設計感
- **Color：** 低刺激暖色環境（米白紙感為底、暖棕文字）；顏色襯托照片不搶照片；金只作細線/分隔/重點點綴；避免純 SaaS 高飽和 accent
- **Photography：** 照片是最大視覺資產——自然光、真實入住感、空間細節、材質、生活痕跡；避免過度 HDR、房仲超廣角、高飽和旅遊廣告感、無目的的人像 lifestyle 照
- **Composition：** 不要求全部置中（Hero 置中、其餘可編輯式不對稱）；圖片與文字形成不對稱平衡；每屏有明確視覺主角；避免大量同尺寸 card grid
- **Shape / UI：** UI 元素退居內容之後；圓角極小（rounded-sm 級）；不把所有資訊包成 card；按鈕不當視覺主角；陰影極淡（紙的厚度，不是浮起卡片）
- **Motion：** 動畫建立節奏不是展示技術——輕微進場、圖片 reveal、hover 微浮起；無 parallax / floating / cursor gimmick；尊重 prefers-reduced-motion

## 05. Signature Moves（招牌動作 2-4 個）

> 小白 2026-08-08 確認：S1 + S2 + S3 + S6

1. **S1 滿版 Hero 照片 + 中央細字排版**——全屏照片、黑罩漸層、白色大字距標題、細線分隔、雙 CTA
2. **S2 信紙式手寫區**——上下金線框、手寫體、左側細線 border-l、右下簽名、角落 MORI 33-3 圓章
3. **S3 細線裝飾語言**——以金線/白線（w-[1px]、gradient 細線、border-y）取代卡片/色塊做分隔與轉場
4. **S6 印章/圓形元素**——MORI 33-3 圓章延伸（房號章、日期章等手工感細節）

全站反覆使用以上特徵形成識別——每個 section 不講不同語言。

## 06. Anti-patterns（本品牌真正禁止的）

> 小白 2026-08-08 確認：1, 5, 6, 9, 10, 11, 16, 17, 18

除非有明確理由，不使用：
1. **深色主視覺**（已實驗否決；黑底=偏離溫暖住宿感）
2. **大量 pill 圓角標籤**（藥丸式）
3. **漸層文字**（gradient text）
4. **每區都 rounded container**（所有內容包圓角框）
5. **巨型 slogan**（佔半屏的超大字口號）
6. **跑馬燈**（無內容意義的 marquee）
7. **房仲式超廣角照片**（魚眼變形空間照）
8. **高飽和旅遊廣告感照片**（顏色鮮豔不真實）
9. **大量滑鼠特效**（parallax / cursor gimmick / floating）

**執行規則：如果 AI 的第一個方案出現上述模式 → 優先尋找第二種構圖，而不是直接實作。**

## 07. Decision Hierarchy（決策順位）

發生視覺衝突時，按照以下順位決策：
1. 使用者是否能快速理解內容
2. 照片是否得到足夠展示
3. 是否符合整體 Art Direction
4. 是否保持跨頁一致性
5. 是否具有美感
6. 是否具有新奇效果

（例：動畫漂亮但妨礙讀房價 → 刪動畫；card 漂亮但讓照片變小 → 拿掉 card）

## 08. Review Questions（每次重要改動後檢查）

1. 第一眼看到的是內容，還是 UI 技巧？
2. 改動是否仍像同一家民宿（把 logo 拿掉還認得出來嗎）？
3. 是否增加了不必要的 card / container？
4. 照片是否仍然是主角？
5. 是否為了「設計感」犧牲閱讀？
6. 如果拿掉動畫，畫面本身還成立嗎？
7. 是否出現典型 AI landing page 語言（pill / gradient / bento / 超大標語）？
8. 與 Benchmark（warm-v1）相比，是真的更好，還是只是更複雜？

**Better ≠ More Designed。**

## 09. 頁面層級 Hard Gates（Sol 壓力測試補丁 v0.2）

> 以下條件屬於頁面／區塊完成前的硬性驗收門檻。任一 Hard Gate 明顯不通過，即不視為完成，不得僅以「更有設計感」或「視覺更新」作為保留理由。

### 房型列表頁
- 房型照片必須明顯大於資訊區塊，並作為每個房型的第一視覺主角
- 不得將主要房型做成大量同尺寸、同權重的商品卡片或四宮格／多宮格卡片牆
- 每個房型必須能在第一眼看出「房型名稱 + 主要空間差異」，不得要求使用者先閱讀大量文字才能理解差異
- 房型之間必須保有明確的段落與呼吸感，不得為提高資訊量而壓縮成訂房平台式密集列表
- UI、標籤、按鈕與裝飾不得比住宿照片更搶眼；若兩者衝突，優先保留照片與閱讀清晰度

### 訂房 CTA 區塊
- 訂房 CTA 必須維持「主人邀請入住」的感受，不得呈現為促銷廣告、SaaS 轉換模組或強迫成交區塊
- 主要行動必須清楚且集中，不得同時出現多個同權重 CTA 互相競爭
- 不得依賴深色大色塊、強烈漸層、巨大按鈕或其他高刺激手段製造轉換壓力
- CTA 區塊即使移除動畫與裝飾後，仍必須靠文字層級、留白與構圖成立
- 信紙、手寫、金線、簽名或 MORI33-3 圓章等元素只能強化「邀請感」，不得妨礙訂房資訊與主要行動的辨識

### Gallery 區塊
- 照片必須是 Gallery 的絕對主角；不得讓框架、卡片、文字或互動效果比照片本身更突出
- 不得將全部照片平均切割成大量同尺寸縮圖；每個主要視覺段落必須存在明確主圖或主次關係
- Gallery 必須維持真實、安靜的住宿與生活感，不得演變成網紅打卡牆、房仲展示頁或高飽和旅遊廣告
- 圖片排列必須保有閱讀節奏與呼吸感，不得為了展示更多照片而形成密集瀑布流或視覺噪音
- Gallery 的互動不得成為設計主角；禁止依賴浮動、追蹤滑鼠、強烈縮放、parallax 等效果建立「設計感」

### 首頁 Hero
- Hero 必須由住宿／空間照片主導，第一眼不能先看到 UI、裝飾或巨大文案
- 不得以深色主視覺、巨大 slogan、SaaS 式功能訴求或精品飯店式戲劇化奢華感取代既有溫暖基底
- Hero 文案必須保持克制且可立即理解，不得為追求 editorial 效果而讓主要訊息難讀、過小或過度抽象
- 照片、標題與必要 CTA 必須存在清楚的主次關係；不得讓所有元素同時爭奪第一視覺
- 動畫只能作為輕微進場與節奏輔助；即使完全關閉動畫，Hero 仍必須成立並維持品牌辨識

### 包棟方案頁
- 第一屏必須能清楚理解「這是包棟方案」以及最核心的入住價值，不得只呈現氣氛而讓方案內容模糊
- 住宿空間與實際使用情境必須比促銷資訊更突出；不得做成價格方案卡、SaaS pricing table 或電商促銷頁
- 包棟包含內容、適合人數、主要空間與必要條件必須容易掃讀，不得為了維持極簡而隱藏關鍵資訊
- 頁面必須延續「有人住過的房子」與真實聚會感，不得轉向婚宴會館、豪宅租賃或精品 Villa 式奢華語言
- CTA 必須自然延續前文內容與邀請感，不得以倒數、限時、巨大促銷色塊或其他高壓轉換手段刺激下單

## 10. Mobile 原則（Sol 壓力測試補丁 v0.2）

- 手機版仍然以照片與內容為主角，不得因螢幕變小就把所有內容改造成卡片、滑動卡或密集 UI
- Desktop 的品牌人格必須延續到 Mobile；不得把手機版退化成一般訂房平台、電商頁或制式 Tailwind 元件排列
- 房型列表在手機版仍應維持「大圖 + 清楚文字段落」的敘事方式，不得壓縮成大量小縮圖與資訊卡
- Gallery 在手機版仍必須保有主圖與節奏變化，不得把所有圖片平均縮成相同尺寸的碎片化圖牆
- 訂房 CTA 在手機版仍應保留「邀請信／主人邀請」的視覺與語氣，不得簡化成一個孤立的大型「立即訂房」按鈕區
- Mobile 可以由雙欄改為單欄，但只能改變排列方式，不得改變原本的視覺優先順序；照片、閱讀、溫暖真實感的順位保持不變
- 不得為了節省垂直空間而過度壓縮 section 間距、文字行距或圖片尺寸；手機頁仍需維持偏慢、有呼吸感的閱讀節奏
- 所有桌面版的 Signature Moves 在手機上可以簡化，但不能被另一套陌生的 Mobile UI 語言取代；若需要取捨，優先保留品牌辨識與閱讀清晰度，而不是裝飾完整度
